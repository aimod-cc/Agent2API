# Agent2API 功能路线与侧栏导航规划

> **v2 —— 扩大样本后的完整版**
>
> 依据：
> ① 同类项目横评 **20+ 个**（见 §二 完整清单）；
> ② 本项目后端 `server/core` 与 `server/api` **逐个 grep 核实**（不凭印象判断缺口）；
> ③ 当前侧栏 12 个页面的真实结构与定位。
>
> 原则：**只列本项目真正缺的、且与本项目定位（个人本地网关 + 账号池）相符的**。
> 中转站商业形态（多用户 / 兑换码 / 在线支付）与企业级治理（SSO / RBAC / 合规审计）
> 一律不列 —— 本项目不是那个形态。

## 四、功能缺口总表（按建议度分级）

### 🟢 第一梯队：值得做，且成本低

| # | 缺口 | 同类依据 | 成本 | 说明 |
|---|---|---|---|---|
| 1 | **试炼场（Playground）** | New API 游乐场、OctaFuse Playground+Simulator、Cherry Studio 多模型并排 | **极低** | `/v1/chat/completions` + `/api/model-test` 已在；缺独立工作台 |
| 2 | **账号健康总览** | workbuddy2api-gui 仪表盘、New API 性能健康、FreeLLMAPI per-key health | **低** | `limiter.rs`/`degrade.rs`/`credential_maintenance.rs` 数据齐全，缺聚合出口 |
| 3 | **报表加「用量与额度」视角** | New API 数据看板、OctaFuse 三套成本口径 | **低** | `billing/usage.rs` 积分明细已就绪 |

### 🟡 第二梯队：值得做，成本中等

| # | 缺口 | 同类依据 | 说明 |
|---|---|---|---|
| 4 | **通知与告警** | OctaFuse Webhook（飞书/企微）、AionUi Telegram/飞书/钉钉 | 后端**完全为零**，要新建发送器 + 事件源。桌面托盘常驻是天然优势 |
| 5 | **冷却/熔断策略可视化** | workbuddy2api 的 429/404/402 三级分级 | 本项目已有冷却逻辑，缺「看得见 + 可调」的界面 |
| 6 | **请求级延迟观测** | CLIProxyAPI 监控模块、Helicone latency | 已有 TTFB 采集，缺分位聚合视图 |

### 🟠 第三梯队：可选，看是否要走这条路

| # | 缺口 | 同类依据 | 取舍 |
|---|---|---|---|
| 7 | **MCP Server（本机对外暴露）** | Cherry Studio MCP | 与现有「三协议」同层，是**新接入形态**；但目标用户（Coding Agent）大多直连 HTTP，优先级低 |
| 8 | **响应缓存（精确匹配）** | Portkey 语义缓存、Helicone 缓存层 | ⚠️ **有反作用**：本项目价值是「把账号额度变成 API」，缓存不消耗额度看似省钱，但会**掩盖路由与账号状态**（排障时看不到真实请求）。建议**不做**，或仅做默认关闭的可选精确缓存 |
| 9 | 提示词版本管理 / A-B | Langfuse | 属于「提示词工程平台」定位，本项目是网关，**边界外** |

### ⛔ 明确不做

| 候选 | 理由 |
|---|---|
| 兑换码 / 钱包 / 充值 / 多用户 / RBAC | 中转站商业形态，本项目单用户本地网关 |
| 模型合议 / 语义路由 / SSO / SCIM | 企业级治理，与账号池轮转定位冲突 |
| RAG / 知识库 | 是**客户端**（Cherry Studio）的职责，网关不该做 |
| 6 层设备标识重置 / 登录态快照切换 | TraeWorkAssistant 是「单客户端多账号切换」，本项目**多账号天然共存**，不需要切换 |
| WebDAV 同步 | 桌面端已有「整库备份/恢复」（`api/backup_api.rs`），同步是过度设计 |

## 五、侧栏导航改动建议

### 推荐方案（净增 2 个一级菜单 + 2 处内嵌）

```
智能
  ├─ AI 助手
  └─ 试炼场                    ← 新增（#1）

运行状态
  ├─ 报表  [标签页：请求量 | 用量与额度]      ← #3
  ├─ 账号
  ├─ 账号健康                  ← 新增（#2）
  └─ 签到中心

转发能力
  ├─ 模型管理
  ├─ 网络代理
  ├─ 网关 Key
  └─ 文档

诊断
  ├─ 请求日志  [加「延迟分位」子视图]          ← #6
  ├─ 日志
  ├─ 定时任务
  └─ 设置  [分类内新增：通知与告警]            ← #4
```

### 为什么不新增更多一级菜单

| 候选 | 处置 |
|---|---|
| 冷却策略 | 并入「设置 → 路由」分类（已有路由分类） |
| 通知与告警 | 并入「设置」新分类 —— **低频配置，不必占一级菜单** |
| 延迟分位 | 并入「请求日志」子视图 —— 同源数据 |
| MCP Server | 并入「文档」页（同属「怎么接进来」） |

**净增 2 个一级菜单**：试炼场、账号健康。其余都是内嵌。
