# Agent Note: 网关推理正文的可逆隐私脱敏

Status: implemented

## Problem

Agent 发给模型的上下文可能包含工具读到的密钥、令牌和个人信息。已有指纹脱敏负责改写客户端特征，不保留逆向映射，不能在模型复述被遮盖的工具参数时还原原值。见 [Issue #634](https://github.com/aimod-cc/Agent2API/issues/634)；界面术语参考 [magpie 的本地脱敏文档](https://usemagpie.ai/docs/zh/masking)。

## Decision

默认不改变网关行为。管理员在「设置 → 安全 → 本地隐私脱敏」分别启用凭据、邮箱和中国大陆手机号、自定义词；管理面用受鉴权保护的 `GET/PUT /api/privacy-masking` 热更新整份设置。设置写入本机数据库，不参加云同步。失败时保留先前配置。

脱敏位于三个外部推理端点的鉴权、容量限制之后，以及任何提供商选路、协议翻译、重试和正文观测之前。只访问对应协议已知的文本、工具参数和工具描述；跟踪 ID、鉴权、签名推理和附件不重写。对同一请求同一原值复用随机占位符；响应层在原有记录与协议翻译之后用该请求的内存映射还原，不在日志或库中持久化映射。SSE 分片按选择、内容块和工具调用独立关联，保留事件顺序与协议结束帧。

## Alternatives considered

- 复用现有指纹词表：最少新增界面和数据，但该词表按提供商决定是否改写、可能删除文本，也没有反向映射，与隐私防护的语义不同。
- 分别在各提供商出站实现：能看到最终协议的每个字段，但覆盖容易随新提供商与重试分叉，也会让未遮盖的入站正文进入现有调试记录。用网关入口及对应出口统一处理，不改变各家鉴权。
- 跨请求维护映射以提升前缀缓存命中：会扩大敏感值的驻留时间和跨请求关联。首版每请求独立随机，牺牲请求间占位符一致性。

## Consequences

这是规则型文本保护，不是文件扫描、远端会话清理或全量数据防泄漏。面板内部助手/管理请求、图片附件、签名或加密块、协议标识不经此变换；开启时独立图像推理端点返回明确错误。被改写的正文需要解析并重新序列化，长请求和响应还原有上限。SSE 遇到可能未完的占位符会在有界队列里等后续分片；截断、改写过的占位符不保证还原。正常回传到客户端的内容会包含原值，对客户端处理与日志仍应按真实数据看待。

## Testing

`node scripts/test-privacy-masking.mjs <agent2api-server>` 启动独立网关和回环上游，验证三种协议的 JSON/SSE 文本和工具参数、未开启时的原样路径、出站鉴权不变、错误与请求隔离。纯 Rust 测试验证识别规则、重叠合并和同请求映射复用。
